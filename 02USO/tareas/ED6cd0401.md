## Objetivos didácticos

- Representar el intercambio de mensajes entre un actor y el sistema.
- Expresar el curso normal, las alternativas y las repeticiones de un caso de uso.
- Comprobar que el diagrama comunica fielmente la descripción del caso.

## Trabajo que debes realizar

Elabora **tres diagramas de secuencia**, uno para cada ficha de biblioteca que aparece más abajo. Trabaja al nivel **actor–sistema**: representa a **A1 Socio** o **A2 Bibliotecario** y al «Sistema de gestión de una biblioteca» como único participante informático. Mantén estos códigos en las fichas y los diagramas. No descompongas el sistema en interfaz, controladores, base de datos, impresora u otros componentes.

Cada diagrama debe representar el curso normal y sus alternativas mediante `alt`, con guardas entre corchetes. Utiliza `loop` cuando el caso indique que se repite una interacción. Puedes anotar las comprobaciones internas del sistema sin convertirlas en participantes nuevos. Las salidas y errores de impresión se comunican al bibliotecario.

## CU1 Reservar libro

**Sistema:** Sistema de gestión de una biblioteca.  
**Actor:** A1 Socio.  
**RF relacionados:** RF-BIB01, RF-BIB02.  
**Descripción:** Un socio desea reservar un libro utilizando su código.

**Precondiciones:** El socio no tiene multas. El libro no está en la biblioteca porque otro socio lo está leyendo.

**Curso normal:**

1. El socio proporciona el código.
2. El sistema comprueba que el código existe.
3. El sistema reserva el libro.

**Alternativa 1, código incorrecto:**

- **3b.** El sistema indica que el código es incorrecto.
- Retorno al paso 1.

**Postcondición:** El libro no podrá ser reservado por otro socio.

La comprobación del paso 2 conduce al paso 3 si el código es correcto y al 3b si es incorrecto. La numeración 3b se conserva como en la ficha de clase. La reserva se realiza una sola vez, después de obtener un código válido.

## CU2 Llevar libro prestado

**Sistema:** Sistema de gestión de una biblioteca.  
**Actor:** A1 Socio.  
**RF relacionados:** RF-BIB02, RF-BIB03, RF-BIB04.  
**Descripción:** El socio solicita un libro mediante su código y se lo lleva prestado.

**Precondiciones:** El socio no tiene penalizaciones. El libro no se encuentra prestado.

**Curso normal:**

1. El socio introduce el código del libro.
2. El sistema comprueba que el código del libro es correcto.
3. El sistema comprueba que el libro se encuentra disponible.
4. El sistema proporciona el libro.

**Alternativa 1:**

- **2.1.** El código del libro es incorrecto.
- **2.2.** El sistema comunica al socio que el código es incorrecto.
- **2.3.** Fin del caso de uso.

**Alternativa 2:**

- **3.1.** El libro no se encuentra disponible.
- **3.2.** El sistema comunica al socio que el libro no se encuentra disponible.
- **3.3.** Fin del caso de uso.

**Postcondición del curso normal:** El libro se asigna como prestado al socio y se lo lleva.

«No prestado» indica que nadie lo tiene en préstamo. Puede no estar disponible por otra causa. En las alternativas este caso termina; no vuelve a pedir el código como CU1.

## CU3 Actualizar catálogo

**Sistema:** Sistema de gestión de una biblioteca.  
**Actor:** A2 Bibliotecario.  
**RF relacionados:** RF-BIB05, RF-BIB06, RF-BIB07.  
**Descripción:** El bibliotecario introduce un nuevo libro en el catálogo.  
**Precondiciones:** Ninguna.

**Curso normal:**

1. El bibliotecario introduce los datos del libro.
2. El sistema asigna un identificador al libro.
3. El sistema registra el libro.
4. El sistema imprime un tejuelo con el código para el libro.

**Alternativa 1:**

- **4.1.** Si no se puede imprimir el tejuelo por un error de impresora:
- **4.1.1.** El sistema informa de que no se ha podido imprimir el tejuelo.
- **4.1.2.** Fin del caso de uso.

**Postcondición:** El libro queda registrado en el sistema. El fallo de impresión sucede después del registro y no lo deshace.
